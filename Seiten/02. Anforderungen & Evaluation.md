## Evaluation der Systemanbindung

### FortiGate
Für die FortiGate soll eine Monitoring-Anbindung evaluiert werden, welche sich in die zentrale Prometheus- und Grafana-Plattform integrieren lässt. Im bestehenden Monitoring der Intecso AG wird primär die Erreichbarkeit der Firewalls überwacht.

Für den MVP wird deshalb die **Erreichbarkeit der FortiGate** als grundlegende Monitoring-Anforderung definiert. Eine detaillierte Erfassung interner Systemmetriken ist nicht zwingend erforderlich.

#### Mögliche Anbindungsvarianten [FortiGate]
1. **Prometheus SNMP Exporter**  
   Die FortiGate stellt System- und Netzwerkmetriken über SNMP bereit. Der SNMP Exporter fragt diese ab und stellt sie Prometheus zur Verfügung. Dadurch ist ein deutlich detaillierteres Monitoring als eine reine Verfügbarkeitsprüfung möglich.

2. **FortiOS REST API / FortiGate Exporter**  
   Über die FortiOS REST API können Systeminformationen und Statistiken abgefragt werden. Für die Integration mit Prometheus kann ein entsprechender Exporter eingesetzt werden. Dafür werden ein API-Administrator und ein API-Token benötigt.

3. **Prometheus Blackbox Exporter**  
   Der Blackbox Exporter überprüft die FortiGate mittels ICMP auf Erreichbarkeit. Dies entspricht weitgehend dem heutigen Monitoring und benötigt keine zusätzlichen Zugangsdaten auf der Firewall.

Eine Einschränkung besteht darin, dass nicht alle betreuten FortiGate Firewalls von der Monitoring-Plattform direkt erreichbar sind. Die Geräte sind jedoch in FortiGate Cloud registriert. FortiGate Cloud bietet Remote-Management und eine Cloud REST API und wird deshalb als mögliche spätere Erweiterung berücksichtigt.

>**Quellen:**
>- [Fortinet – FortiGate SNMP](https://docs.fortinet.com/document/fortigate/7.4.0/administration-guide/62595/snmp)
>- [Fortinet – FortiOS API](https://docs.fortinet.com/document/fortigate/6.4.9/administration-guide/940602/using-apis)
>- [Prometheus – SNMP Exporter](https://github.com/prometheus/snmp_exporter/tree/main/generator)
>- [Prometheus – Blackbox Exporter](https://github.com/prometheus/blackbox_exporter)

>- [Prometheus Community – FortiGate Exporter](https://github.com/prometheus-community/fortigate_exporter)

#### Bewertung der Anbindungsvarianten [FortiGate]
Die Varianten werden auf einer Skala von **1 bis 5** bewertet. Eine hohe Punktzahl bedeutet eine gute Erfüllung des jeweiligen Kriteriums.

| Kriterium | Gewichtung | SNMP Exporter | REST API / FortiGate Exporter | Blackbox Exporter |
|---|---:|---:|---:|---:|
| Abdeckung der MVP-Anforderungen | 25 % | 5 | 5 | 5 |
| Direkte Prometheus-Integration | 20 % | 4 | 4 | 5 |
| Implementierungsaufwand | 20 % | 3 | 2 | 5 |
| Netzwerk und Sicherheit | 15 % | 3 | 3 | 4 |
| Berechtigungen und Abhängigkeiten | 10 % | 3 | 2 | 5 |
| Laufende Kosten | 10 % | 5 | 5 | 5 |
| **Gewichtetes Ergebnis** | **100 %** | **3,85** | **3,55** | **4,80** |

##### SNMP Exporter

**Vorteile:**
- Detaillierte System- und Netzwerkmetriken
- Read-only-Zugriff auf die FortiGate
- Direkte Integration in Prometheus

**Nachteile:**
- Zusätzliche SNMP-Konfiguration notwendig
- Höherer Aufwand als für eine reine Erreichbarkeitsprüfung
- Direkte Netzwerkerreichbarkeit zur FortiGate erforderlich

**Kosten:**  
Keine zusätzlichen Lizenzkosten. Es entsteht Betriebs- und Konfigurationsaufwand.

##### FortiOS REST API / FortiGate Exporter

**Vorteile:**
- Abfrage detaillierter FortiGate-Informationen
- Prometheus-Integration über einen Exporter
- Kommunikation über HTTPS

**Nachteile:**
- API-Administrator und Token notwendig
- Zusätzliche Secrets müssen verwaltet werden
- Community-basierter Exporter als zusätzliche Abhängigkeit
- Höherer Aufwand als für den benötigten MVP-Umfang

**Kosten:**  
Für den Exporter fallen keine Lizenzkosten an. Zusätzlicher Aufwand entsteht für Konfiguration, Token-Verwaltung und Betrieb.

##### Blackbox Exporter

**Vorteile:**
- Sehr geringer Implementierungsaufwand
- Direkte Integration in Prometheus
- Keine Zugangsdaten auf der FortiGate notwendig
- Entspricht dem heutigen Verfügbarkeitsmonitoring

**Nachteile:**
- Keine internen Systemmetriken
- Direkte ICMP-Erreichbarkeit notwendig
- Nicht für alle betreuten FortiGate Firewalls einsetzbar

**Kosten:**  
Keine zusätzlichen Lizenzkosten. Es entsteht lediglich Betriebs- und Konfigurationsaufwand innerhalb der eigenen Monitoring-Plattform.

#### Empfehlung für den MVP [FortiGate]

Für den MVP wird die **Erreichbarkeitsüberwachung über den Prometheus Blackbox Exporter mittels ICMP** gewählt. Sie erfüllt die definierten Anforderungen mit dem geringsten Implementierungs- und Betriebsaufwand.

Für nicht direkt erreichbare Firewalls wird **FortiGate Cloud** als mögliche spätere Erweiterung dokumentiert. Eine Integration der Cloud REST API ist nicht Bestandteil des MVP.

### Azure Windows Server
Für die Azure Windows Server VM soll eine Monitoring-Anbindung evaluiert werden, welche sich in die zentrale Prometheus- und Grafana-Plattform integrieren lässt. Die Anforderungen orientieren sich an den heute überwachten Azure Windows Server VMs der Intecso AG und deren Kundschaft.

Im bestehenden Monitoring werden abhängig vom Server unter anderem folgende Werte überwacht:

- Erreichbarkeit mittels Ping
- CPU-Auslastung
- Arbeitsspeicherauslastung
- freier Speicherplatz einzelner Laufwerke
- System-Uptime
- Pagefile-Auslastung
- Erreichbarkeit von RDP
- Status betriebsrelevanter Dienste und Applikationskomponenten
- DNS-Funktion beziehungsweise DNS-Dienste

Bei den Diensten kann es sich sowohl um Windows-Systemdienste als auch um Komponenten von Drittanbieter-Applikationen, Datenbanken oder kundenspezifischen Fachanwendungen handeln.

Für den MVP werden **Ping, CPU-Auslastung, Arbeitsspeicher, freier Speicherplatz und System-Uptime** als grundlegende Monitoring-Anforderungen definiert. RDP, Pagefile, DNS und applikationsspezifische Dienste gelten als optionale Erweiterungen.

---

#### Mögliche Anbindungsvarianten [Azure Windows VM]
1. **Prometheus Windows Exporter**  
   Der windows_exporter wird auf der Windows Server VM installiert und stellt System- und Applikationsmetriken direkt im Prometheus-Format bereit. Über verschiedene Collector können unter anderem CPU, Arbeitsspeicher, Laufwerke, Netzwerk, Pagefile und Dienste überwacht werden.

2. **Azure Monitor mit Azure Monitor Agent**  
   Azure Monitor stellt eine native Azure-Lösung zur VM-Überwachung bereit. Hostmetriken werden teilweise automatisch erfasst. Für Gastmetriken und Protokolle können der Azure Monitor Agent und Data Collection Rules eingesetzt werden.

3. **Windows Exporter mit Blackbox Exporter**  
   Der windows_exporter erfasst interne Systemmetriken. Der Blackbox Exporter ergänzt externe Verfügbarkeitsprüfungen über beispielsweise ICMP, TCP oder HTTP/HTTPS.

>**Quellen:**
>- [Prometheus Community – windows_exporter](https://github.com/prometheus-community/windows_exporter)
>- [Microsoft Learn – Überwachen virtueller Computer in Azure](https://learn.microsoft.com/de-de/azure/azure-monitor/vm/monitor-vm)
>- [Microsoft Learn – Gastprotokolle und Metriken einer Azure VM sammeln](https://learn.microsoft.com/de-de/azure/azure-monitor/vm/tutorial-monitor-vm-guest)
>- [Prometheus – Blackbox Exporter](https://github.com/prometheus/blackbox_exporter)

#### Bewertung der Anbindungsvarianten [Azure Windows VM]
Die Varianten werden auf einer Skala von **1 bis 5** bewertet. Eine hohe Punktzahl bedeutet eine gute Erfüllung des jeweiligen Kriteriums.

| Kriterium | Gewichtung | Windows Exporter | Azure Monitor | Windows + Blackbox Exporter |
|---|---:|---:|---:|---:|
| Abdeckung der MVP-Metriken | 25 % | 5 | 4 | 5 |
| Direkte Prometheus-Integration | 20 % | 5 | 2 | 5 |
| Implementierungsaufwand | 15 % | 4 | 3 | 3 |
| Netzwerk und Sicherheit | 15 % | 3 | 5 | 3 |
| Berechtigungen und Abhängigkeiten | 10 % | 4 | 3 | 4 |
| Laufende Kosten | 15 % | 5 | 2 | 5 |
| **Gewichtetes Ergebnis** | **100 %** | **4,45** | **3,20** | **4,30** |

##### Windows Exporter

**Vorteile:**
- Direkte Prometheus-Integration
- Deckt die benötigten MVP-Systemmetriken ab
- Zusätzliche Collector für Pagefile, Dienste, DNS und weitere Komponenten
- Keine zusätzlichen Lizenzkosten
- Konfiguration versionierbar

**Nachteile:**
- Zusätzlicher Dienst auf der VM
- Prometheus benötigt Netzwerkzugriff auf den Exporter
- Endpunkt und Firewall-Regel müssen abgesichert werden

**Kosten:**  
Keine Lizenzkosten. Aufwand entsteht für Installation, Konfiguration und Betrieb.

##### Azure Monitor mit Azure Monitor Agent

**Vorteile:**
- Native Azure-Integration
- Zentrale Konfiguration über Data Collection Rules
- Host-, Gast- und Logdaten können erfasst werden
- Keine direkte Prometheus-Verbindung zur VM erforderlich

**Nachteile:**
- Keine direkte Integration der Gastmetriken in die eigene Prometheus-Instanz
- Zusätzliche Azure-Abhängigkeit
- Höherer Integrationsaufwand für die geplante Plattform
- Kosten abhängig von der verwendeten Datensammlung

**Kosten:**  
Azure-Hostmetriken werden teilweise kostenlos bereitgestellt. Für Gastprotokolle fallen jedoch Aufnahme- und Speichergebühren an. Je nach Konfiguration können weitere Azure-Monitor-Kosten entstehen.

##### Windows Exporter mit Blackbox Exporter

**Vorteile:**
- Interne Systemmetriken und externe Verfügbarkeitsprüfungen kombinierbar
- ICMP-, TCP-, HTTP- und HTTPS-Prüfungen möglich
- Direkte Integration in Prometheus
- Keine zusätzlichen Lizenzkosten

**Nachteile:**
- Zwei Exporter müssen betrieben werden
- Zusätzliche Netzwerk- und Firewall-Konfiguration
- Höherer Implementierungsaufwand

**Kosten:**  
Keine Lizenzkosten. Gegenüber dem alleinigen Windows Exporter entsteht zusätzlicher Betriebs- und Konfigurationsaufwand.

#### Empfehlung für den MVP [Azure Windows VM]
Für den MVP wird der **Prometheus Windows Exporter** bevorzugt. Er deckt die definierten Systemmetriken direkt ab, lässt sich ohne zusätzliche Azure-Monitor-Abhängigkeit in Prometheus integrieren und verursacht keine zusätzlichen Lizenzkosten.

Der **Blackbox Exporter** kann später ergänzend eingesetzt werden, wenn externe Verfügbarkeits- oder Dienstprüfungen benötigt werden.
